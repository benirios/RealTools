## The problem (confirmed by direct read)

RealTools' core promise is `create deal → generate OM → send to buyers → track
opens`. The **tracking (receiving) end is fully built and well-hardened**. The
**sending end does not exist anywhere**, and the product pivoted from the old
`buyers` model to the `investors` model mid-build, orphaning distribution.

Built and good — do not rebuild:
- `app/om/[id]/page.tsx` — public OM page, no auth (middleware excludes `/om/*`)
- `lib/tracking/record-om-open.ts` — idempotent first-open claim (atomic null
  predicate in the UPDATE so URL + pixel can't double-count). This is the hard part.
- `app/api/track/[token]/route.ts` — pixel fallback
- Activity renderer already handles `om_sent` / `om_opened`

Broken at every node (send end):
| Node | State | Evidence |
|---|---|---|
| Add a buyer/investor recipient | no send UI | no `components/*buyer*`, no send dialog |
| Mint `tracking_token` | never written | token only read in `record-om-open.ts:35` |
| Send email (Resend) | never called | `createResendClient()` in `lib/resend.ts` has zero callers |
| Emit `om_sent` | never fired | `om_sent` only in UI render + types column |

## Decision (locked by user)

**Build distribution on the INVESTOR model**, not the legacy `buyers` model.
Rationale: all v1.3–v1.6 data + scoring live on `investors` /
`investor_listing_matches`; the matched-investor list is the natural recipient
picker. The investor page already has the intended slot — currently a stub:
`app/(app)/investors/[id]/page.tsx:~718` `ExportsTab` →
`"TODO: ...memorandos e pacotes prontos para enviar ao cliente"`.

## Schema facts (verified against `types/supabase.ts`)

- `investors` HAS `email: string | null` and `user_id: string`. Good for Resend.
  (Email is nullable — guard sends against null email.)
- `investor_listing_matches` has `investor_id`, `listing_id`, `user_id`,
  `match_score`, etc. It does **NOT** have `tracking_token` / `om_sent_at` /
  `om_opened_at`.
- `deal_buyers` (legacy) HAS the exact column triad we want to copy:
  `tracking_token`, `om_sent_at`, `om_opened_at`.
- **BLOCKER:** `activities.deal_id` is `NOT NULL` and FKs to `deals`. Investor
  sends have **no deal**, so investor `om_sent`/`om_opened` events **cannot** be
  written to `activities` as-is. → Route around it: the send-table carries its
  own `om_sent_at` / `om_opened_at` state. Skip the deal-scoped activity feed for
  investor sends in v1. (Revisit later if a unified event log is wanted.)

## Build plan

### 1. Migration `020_investor_om_sends.sql`
New dedicated send table (one row per send; a match can be re-sent, so don't
pollute the deterministic match record):
```sql
create table investor_om_sends (
  id uuid primary key default gen_random_uuid(),
  user_id text not null,                 -- TEXT: Clerk era, post-019
  listing_id uuid not null references listings(id) on delete cascade,
  investor_id uuid not null references investors(id) on delete cascade,
  tracking_token text not null unique default gen_random_uuid()::text,
  om_sent_at timestamptz,
  om_opened_at timestamptz,
  created_at timestamptz default now()
);
create index on investor_om_sends (listing_id);
create index on investor_om_sends (tracking_token);
-- RLS stays OFF (per migration 019 / Clerk app-layer filtering). Filter by user_id in code.
```

### 2. Generalize the open recorder
`lib/tracking/record-om-open.ts` is hard-coded to `deal_buyers` / `buyers`. Add a
sibling `recordInvestorOmOpenByToken(token)` (or parametrize the table) that runs
the **same** atomic claim against `investor_om_sends`:
```
update investor_om_sends set om_opened_at = now()
  where tracking_token = $1 and om_opened_at is null
  returning listing_id, investor_id
```
No activity insert (FK blocker). The send-row timestamp IS the record.

### 3. `sendOmAction` — `lib/actions/om-actions.ts` (new)
```
const { userId } = await auth(); if (!userId) throw ...
for each selected investor (must have non-null email):
  upsert investor_om_sends row (token auto-generated by default, or crypto.randomUUID())
  set om_sent_at = now()
  Resend: createResendClient().emails.send({ to: investor.email, ... link below })
revalidatePath the listing page
```
Use the **service-role** client for writes (RLS off), but ALWAYS pass
`user_id: userId` and filter reads by it — that's the only tenant wall.

### 4. Email template — `lib/email/om-template.tsx` (new)
- Primary link: `${NEXT_PUBLIC_SITE_URL}/om/${listingId}?ref=${token}`
- Secondary 1px pixel: `.../api/track/${token}`
- (Note: `/om/[id]` currently reads `deals`, not `listings` — confirm whether the
  public OM page must also serve a listing, or whether investor OMs point at a
  deal-backed OM. If listings need a public OM page, that's an extra sub-task.)

### 5. Send UI — replace `ExportsTab` stub
`SendOmDialog` on the listing or investor page. Recipient picker fed by ranked
`investor_listing_matches` for the listing. Disable rows where `investor.email`
is null.

### 6. Recipients view — `OmRecipientsCard` (new)
Read `investor_om_sends` for the listing: show sent / opened / when per investor.
